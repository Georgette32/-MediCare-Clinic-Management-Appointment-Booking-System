# Integration contracts

- **Identity:** shared `AppointmentDbContext` extends ASP.NET Core `IdentityDbContext<IdentityUser>`. User IDs are used as patient and doctor IDs in this standalone starter. A team Identity context should replace or be merged with this context before combining modules; do not create parallel users.
- **Doctor queue sessions:** `DoctorQueueSession.DoctorId` is the authenticated Identity user ID. Doctor/Admin MVC actions pass only `UserKey` from claims and session service methods scope reads and mutations by both session ID and doctor ID. Admin retains the existing self-scoped behavior; no cross-doctor permission was added. Queue entries keep their current session association; append-only `AppointmentEvents.DoctorQueueSessionId` records the session for queue lifecycle events so later re-association does not erase the event trail. Session creation is explicit, followed by manual start and manual close. No background worker starts or closes sessions. On session close, a still-called patient is returned to Waiting and its call timestamps are cleared; legacy unassociated calls are similarly recovered on explicit session start. Legacy InConsultation entries are attached to the new active session and remain completable; they are not marked completed automatically.
- **Patients / Doctors:** no team entities were present. Supply stable user/doctor IDs, doctor specialization, and clinic time-zone data through the owning module or adapters. Provision doctor scheduling settings and working-hour rows before enabling booking.
- **Notifications:** `IAppointmentNotifier.OfferCreatedAsync` persists an in-app notification in the appointment database and patient inbox. This repository contains no Georgette Notifications, SignalR, or email integration contract/implementation. Appointment absence/reschedule, duration-decision, and general queue notifications are not yet delivered through that module. Integrate through a transactional outbox and idempotent event key when the owning module's contract is available.
- **Analytics:** consume `AppointmentEvents` and UTC timestamps. Event types include AppointmentBooked, AppointmentCancelled, AppointmentRescheduled, PatientCheckedIn, WalkInArrived/Approved/Rejected/Deferred, PatientCalled, ConsultationStarted/Ended, and WaitingListOfferCreated/Accepted/Declined.
- **Frontend:** MVC routes provide patient doctor search, availability-based booking, appointment history filters, cancel/reschedule/check-in, notifications, and waiting-list actions. Doctors have daily schedule, FullCalendar, queue, and schedule settings pages.
- **Migrations:** review `InitialCreate` alongside the shared project's migration history before merging contexts. EF CLI is pinned to 10.0.14 in `dotnet-tools.json`, matching EF runtime/packages. The `AppointmentQueueHardeningAndDurationSnapshot` Down migration drops event session references, appointment duration snapshots, and associated constraints; rollback loses this audit/snapshot data. Apply with `dotnet tool run dotnet-ef database update --project MediCare.Infrastructure --startup-project MediCare.Web`.
- **Duration model and Assistant:** no statistical model or Assistant role existed in this standalone repository. `DefaultConsultationDurationMinutes` remains the locally configured approved duration; suggestion generation/review workflow and Assistant account provisioning require the model/identity owner's integration contract and are not implemented here.
